## 1. 文档定位与适用范围

本文档用于指导一个功能点需要配置时，判断采用什么配置方式承载。它只回答两个问题：配置逻辑上需要几个容器、配置容器用什么形式。上游文档 [导航菜单与信息层级拆解](../01-navigation-and-hierarchy.md) 负责配置入口归属与容器类型选择（独立菜单级配置页、页面内轻量入口、弹窗或抽屉）；本文档承接其结论，判断配置的组织方式与形式。

与其他文档的分工边界：

- 配置入口归属与容器类型（页面、抽屉、弹窗）的选择：由 [导航菜单与信息层级拆解](../01-navigation-and-hierarchy.md) 与 [配置页容器选择规则](../../02-template/01-page-types.md#配置页容器选择规则) 判断，本文档不重复。
- 配置容器内的具体表单项、字段组件、校验、分组、步骤条等表单规则：见 [通用表单设计方法](form-patterns.md)，本文档只约束容器结构与配置形式，不决定表单项怎么配置。
- 已配置内容用表格承载时的工具栏、字段列、分页等完整规则：见 [表格与数据管理](table-patterns.md)。
- 组件选型：按本文档确定配置形式后，联动 [idux组件映射](../../05-components/idux-component-map.md)。

适用对象：全局配置、功能配置（如统一策略设置、水印样式配置、第三方平台对接、流程或策略编排）等需要用户配置的功能点；新增、编辑单条业务对象数据的表单不在此范围，直接按 form-patterns.md 处理。

## 2. 配置方式判断逻辑

按以下两步判断，先定配置逻辑，再定配置形式。

### 第一步：确定配置逻辑与容器数量

1. 单实例配置（单容器）：功能点的配置内容由一份配置数据完整表达，配置项全局唯一或针对单一对象统一生效，例如全局开关、统一阈值、水印样式、单条流程定义。此时只需要一个配置容器承载，容器选页面、抽屉还是弹窗按 01-navigation 判断入口归属。
2. 多实例配置（双容器）：功能点需要新增多条结构相同、内容不同的配置项共同完成，例如多条告警规则、多个转发策略、多个第三方平台对接。此时需要两个容器：已配置内容展示容器（承载已配置条目的集合）和新增配置容器（承载单条配置的新增与编辑）。已配置内容容器用表格还是多卡片按第 7 节判断；新增配置容器的类型按 01-navigation 判断。

双容器结构：

```
已配置内容容器（列表页或 Tab 内区块）
  │  工具栏 [新增]
  └────→ 新增配置容器（弹窗/抽屉/页面，按 01-navigation 判断）
```

判断信号：需求描述出现全局、唯一、统一设置时倾向单实例；出现多条、添加、批量管理配置项时倾向多实例。需求未明确时先确认该功能点的配置是否需要多条并存才能完整生效。

### 第二步：确定配置形式

对配置容器按以下决策链选择形式，命中即停，按顺序判断：

1. 配置对象之间存在流程、链路、依赖等结构性关系，需要连线或拖拽表达 → 可视化编排（第 6 节）。
2. 用户需要实时查看配置效果来理解配置逻辑，或配置带有视觉效果需要所见即所得，且效果可由前端即时渲染 → 表单配置加实时预览（第 4 节）。
3. 配置无需实时可视辅助，但需要在提交配置前预览确认配置内容、避免配错 → 表单配置加手动预览（第 5 节）。
4. 配置结果就是数据本身，不存在需要查看的呈现效果 → 纯表单配置（第 3 节）。

速查表：

| 配置特征 | 配置逻辑 | 配置形式 | 关键边界 |
| --- | --- | --- | --- |
| 配置结果为参数、阈值、规则等数据本身，无呈现效果 | 单容器或双容器 | 纯表单配置（3） | 表单项与校验按 form-patterns.md |
| 需要实时查看配置效果辅助理解配置逻辑，或视觉效果类配置，效果可前端即时渲染 | 通常单容器 | 表单配置加实时预览（4） | 预览区随表单输入即时同步，无需用户触发 |
| 无需实时可视辅助，提交前需预览确认配置内容避免配错 | 通常双容器 | 表单配置加手动预览（5） | 用户点击触发，预览结果在独立区块展示 |
| 配置对象间存在流程、链路、依赖等结构性关系 | 单实例单容器，多实例双容器 | 可视化编排（6） | 多实例时编排列表遵循 table-patterns.md |

同一功能点同时命中多种特征时，按决策链顺序取靠前的形式；预览类形式与编排互斥，不允许叠加使用。

## 3. 纯表单配置

### 适用场景

配置结果是参数、阈值、开关、规则条件等数据本身，用户填完保存即完成配置，不需要查看配置生效后的呈现效果。这是配置方式的默认形式，未命中第 4、5、6 节条件时一律使用本形式。

### 使用约束

- 容器结构：单实例时仅一个配置容器；多实例时作为双容器中的新增配置容器。
- 表单布局、字段组件、校验、分组、默认值全部按 [通用表单设计方法](form-patterns.md) 执行，本文档不重复。
- 容器类型联动 `IxProForm`（配置表单页）、`IxProFormModal`（表单弹窗）、`IxProFormDrawer`（表单抽屉），选择依据见 form-patterns.md 表单承载方式。
- 纯表单配置的容器布局与操作按钮直接使用页面模板：配置表单页见 [配置表单页模板](../../02-template/01-page-types.md#110-配置表单页)，表单弹窗与表单抽屉分别见 1.12、1.13 节，本文档不重复画线框。

### 边界

- 配置项本身呈现效果可被预览时，升级为第 4 或第 5 节；不要在纯表单上额外追加预览入口。
- 保存后的配置内容查看属于详情展示范畴，按 [详情页信息展示形式](detail-info-patterns.md) 处理。

## 4. 表单配置加实时预览

### 适用场景

配置逻辑抽象，需要用户实时查看效果来理解配置的作用，或配置带有视觉效果需要所见即所得（样式、布局、内容模板等），且效果可由前端即时渲染。预览区随表单输入同步更新，用户边配置边确认，无需用户触发。

### 使用约束

- 容器结构：配置区与预览区同屏并排，整体在同一个配置容器内，不拆两个容器。
- 布局：表单配置区在左，实时预览区在右；预览区固定可见，不折叠、不放入弹窗。
- 确定与取消操作放在表单配置区底部左侧并左对齐，预览区不承载操作按钮。
- 需求为水印配置、自定义提示页、全屏预览等完整实时预览业务时，页面骨架与预览交互联动 [实时预览配置主题](../../01-theme/live-preview-config.md)。
- 预览区是业务效果的渲染区，非通用表单组件；idux 映射表未覆盖预览区组件时由业务效果输入确认，不得私自假设。

### 线框图

```
┌─ 配置容器 ────────────────────────────────────────────┐
│ ┌─ 表单配置区 ─────────────┐  ┌─ 实时预览区 ────────┐ │
│ │ 名称：[_____________]    │  │                     │ │
│ │ 提示文案：[_________]    │  │  （最终呈现效果     │ │
│ │ 水印样式：[选择____]     │  │    即时渲染）       │ │
│ │ 生效范围：[选择____]     │  │                     │ │
│ │                          │  │                     │ │
│ │ [确定] [取消]            │  │                     │ │
│ └──────────────────────────┘  └─────────────────────┘ │
└──────────────────────────────────────────────────────┘
```

### 边界

- 效果需要模拟、计算或后端参与才能呈现时，改用第 5 节手动预览；不要让用户等待不可控的实时渲染。
- 预览目的仅为提交前一次性确认配置内容、无需持续可视辅助时，改用第 5 节手动预览。
- 预览仅呈现效果，不承担配置编辑职能；预览区内不出现可编辑字段。

## 5. 表单配置加手动预览

### 适用场景

预览的作用是让用户在提交配置前最终确认配置内容、避免配错，配置本身无需实时可视辅助。典型场景：配置项多或影响面大，需要一次性完整预览检查；或效果需要模拟、计算或后端参与才能呈现，例如策略命中模拟、流量推演、下发结果推演。预览由用户点击按钮主动触发。

### 使用约束

- 容器结构：与第 4 节相同，配置区与预览结果区在同一个配置容器内；预览结果区初始为空状态，用户点击预览后展示结果。
- 预览按钮放在表单区底部的操作区，不与确定、取消混排。
- 预览结果在独立容器中展示，不与表单同区混排，独立容器的选择遵循 01-navigation 容器规则。
- 结果预览的承载方式按配置流程二选一：作为步骤条的最后一步；或作为表单提交后自动弹出的结果确认弹窗。两者均只做结果确认，不在预览容器内修改配置项。
- 预览结果为空时按 [状态规范](../05-state-patterns.md) 展示空状态；预览失败时展示异常态与重试入口。
- 预览结果内容按 [详情页信息展示形式](detail-info-patterns.md) 选择展示形式（描述列表、表格、时间轴等）。
- 表单项规则按 form-patterns.md 执行。

### 线框图

```
┌─ 配置容器（表单）────────────────────────────────────┐
│ 名称：[____________________]                          │
│ 命中条件：[____________________]                      │
│ 执行动作：[____________________]                      │
│              [预览]                  [确定]  [取消]   │
└──────────────────────────────────────────────────────┘

        点击 [预览] 后，结果在独立容器中展示，两种承载二选一：

方式一：步骤条最后一步
┌─ 配置容器（步骤条 第N步 共N步：结果预览）────────────┐
│ ① 基础配置 ─ ② 高级配置 ─ ● ③ 结果预览              │
│ ┌─ 预览结果区 ────────────────────────────────────┐ │
│ │ 模拟结果（按详情页信息展示形式渲染）             │ │
│ └──────────────────────────────────────────────────┘ │
│                        [上一步]    [确定并保存]      │
└──────────────────────────────────────────────────────┘

方式二：表单提交后自动弹出的结果确认弹窗
┌─ 配置容器（表单，提交后触发）─────┐  ┌─ 结果预览弹窗 ──┐
│ （表单内容，提交动作触发预览）     │→│ 模拟结果         │
│                                   │  │ （只读确认）     │
│                                   │  │          [关闭]  │
└───────────────────────────────────┘  └──────────────────┘
```

### 边界

- 需要实时查看效果辅助理解配置逻辑或属于视觉效果类配置时，改用第 4 节实时预览。
- 本形式聚焦提交前的确认动作，预览是一次性检查，不承担边配置边理解的持续辅助职能。
- 多实例配置中本形式通常作为双容器的新增配置容器形式；单实例配置中直接作为唯一容器形式。

## 6. 可视化编排

### 适用场景

配置对象之间存在流程、链路、依赖等结构性关系，需要画布拖拽、连线表达节点流转，例如流程编排、策略编排、链路编排。表单无法自然表达对象间的结构关系时使用本形式。

### 使用约束

- 容器结构遵循第一步判断：单实例编排（全局唯一的流程定义）直接进入画布，单容器；多实例编排为双容器，编排列表承载已配置的编排集合，画布编辑承载单条编排。
- 多实例编排的列表遵循 [表格与数据管理](table-patterns.md)，通过行操作进入画布编辑。
- 画布内节点配置通过节点详情弹窗或侧栏表单承载，表单规则按 form-patterns.md 执行；弹窗嵌套遵循 01-navigation 层级规则，画布内不再打开抽屉或页面。
- 画布组件在 idux 映射表未覆盖时，不得私自替代，按 form-patterns.md 产品实现层规则输出组件缺口说明，并给出现有组件组合方案与新增组件需求两种建议。

### 线框图

单实例编排（单容器）：

```
┌─ 编排画布容器 ────────────────────────────────────────┐
│ [撤销] [重做] [缩放] [自动布局]        [确定] [取消]  │
│ ┌─ 画布区 ─────────────────────────────────────────┐ │
│ │                                                  │ │
│ │  [开始] ──→ [节点A] ──→ [条件判断] ──→ [节点B]    │ │
│ │                          │                       │ │
│ │                          └──→ [节点C] ──→ [结束] │ │
│ │                                                  │ │
│ └──────────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────────┘
```

多实例编排（双容器）：

```
编排列表（表格，遵循 table-patterns.md）
  │  行操作 [编辑]
  └────→ 编排画布容器（画布结构同上）
```

### 边界

- 对象之间不存在结构性关系、仅是并列的配置项时，退回表单类形式（第 3-5 节）；不要为并列数据引入画布。
- 画布仅表达结构与流转，节点内字段编辑职责归表单，不在画布上直接铺开编辑字段。

## 7. 双容器场景的已配置内容承载

多实例配置的已配置内容展示容器，按以下两种形式选择：

### 7.1 表格承载

### 适用场景

各配置条目字段结构一致、字段较多、数据量大，或需要筛选、排序、分页管理。完整表格规则见 [表格与数据管理](table-patterns.md)。

### 线框图

```
┌─ 已配置内容容器（列表页或 Tab 内区块）────────────────┐
│ [新增]                  [搜索____________]     [刷新] │
│ ┌────────┬──────────────┬────────┬──────────────┐    │
│ │ 名称   │ 配置内容     │ 状态   │ 操作         │    │
│ ├────────┼──────────────┼────────┼──────────────┤    │
│ │ 规则A  │ xxx          │ 已启用 │ 编辑  删除   │    │
│ │ 规则B  │ xxx          │ 已禁用 │ 编辑  删除   │    │
│ └────────┴──────────────┴────────┴──────────────┘    │
└──────────────────────────────────────────────────────┘
```

### 7.2 多卡片承载

### 适用场景

满足任一条件时使用多卡片：

- 配置条目字段较少，且最终配置数量可控，卡片让每条配置一眼可辨。
- 需要更丰富的视觉效果，常见于与第三方平台对接的场景，例如存储在外部服务器、对接第三方厂商；卡片可承载平台图标、连接状态、对接进度等表格不易表达的信息。

### 使用约束

- 卡片按网格排布，每张卡片对应一条配置；卡片内字段按 [详情页信息展示形式](detail-info-patterns.md) 第 5 节的卡片规则组织，折叠卡片规则同样适用。
- 卡片上的操作保持轻量（编辑、删除、启停）；批量管理需求明显时改用表格承载。
- 第三方对接卡片的连接状态展示遵循 [状态规范](../05-state-patterns.md)。

### 线框图

```
┌─ 已配置内容容器（列表页或 Tab 内区块）────────────────┐
│ [新增]                            [搜索____________]  │
│ ┌─ 卡片 ──────────┐  ┌─ 卡片 ──────────┐             │
│ │ [平台图标]       │  │ [平台图标]       │             │
│ │ 厂商A存储        │  │ 厂商B存储        │             │
│ │ 状态：已连接     │  │ 状态：未连接     │             │
│ │ 空间：已用 60%   │  │ 空间：未初始化   │             │
│ │ [编辑] [删除]    │  │ [编辑] [删除]    │             │
│ └─────────────────┘  └─────────────────┘             │
└──────────────────────────────────────────────────────┘
```

### 选择边界

| 已配置内容特征 | 承载形式 |
| --- | --- |
| 字段多、数据量大、需要筛选排序分页 | 表格（7.1） |
| 字段少、配置数量可控 | 多卡片（7.2） |
| 需要图标、连接状态、进度等丰富视觉表达（常见于第三方对接） | 多卡片（7.2） |
| 两种特征同时存在，以管理效率优先 | 表格（7.1） |

## 8. 组合与输出要求

- 判断顺序固定：先按第一步确定配置逻辑与容器数量，再按第二步确定配置形式；双容器确认后再按第 7 节确定已配置内容承载。
- 本文档结论落到设计稿时，配置容器内的表单细节一律引用 form-patterns.md，不在此重复表单规则；已配置内容为表格时引用 table-patterns.md。
- 设计输出需标明：配置逻辑（单实例或双实例）、配置形式编号（3-6）、容器类型及其判断来源（01-navigation 判断链）、已配置内容承载形式（7.1 或 7.2），便于评审追溯。
- 操作按钮统一规则：双按钮为 [确定] [取消] 顺序不变；弹窗内按钮一律靠右；只读弹窗仅保留一个 [关闭] 按钮，不使用关闭加确认的双按钮组合。
- 新增配置容器点击 [确定] 后返回已配置内容容器并刷新展示新增条目；容器层级与关闭行为遵循 01-navigation 层级规则。
