## 1. 定位与适用范围

本方法用于概览表格页（页面类型 ID：`page-table-overview`）与概览左树表格页（页面类型 ID：`page-table-overview-tree`）顶部概览统计区的卡片样式选择、单卡片结构与组合排序，帮助用户在阅读表格前直观掌握数据总体情况。

页面容器、概览区与表格的位置关系和间距由页面模板定义（见 [概览表格页](../../02-template/01-page-types.md#13-概览表格页) 与 [概览左树表格页](../../02-template/01-page-types.md#14-概览左树表格页)）；概览统计区属于页面级概览、不作为对象主信息区的定位说明见 [01-navigation-and-hierarchy.md](../01-navigation-and-hierarchy.md) 3.2 节。本文只回答两个问题：每张卡片用什么样式、多张卡片如何组合排序。

Dashboard 页面复用第 2、3 节的样式选择与单卡片结构；第 4 节的组合数量与排序约束只约束概览表格页与概览左树表格页的概览区，Dashboard 卡片数量与布局按其页面模板执行。

产品实现层：卡片容器统一使用 `IxCard`；统计数字使用 `IxStatistic` 承载；饼图状态分布使用 `IxPieChart`，横向条形图 TopN 使用 `IxBarChart`（横向条形形态），曲线趋势图使用 `IxLineChart`。组件形态与样式变体编号以 [idux 组件映射表](../../05-components/idux-component-map.md) 为准。

## 2. 卡片样式选择决策链

先明确该卡片要回答的问题，再按下表选择样式：

| 卡片要回答的问题 | 选择样式 | 判断要点 |
| --- | --- | --- |
| 这类对象一共有多少 | 纯数字统计 | 只需一个总量，无拆分诉求，如应用数 80 |
| 总量按子类拆开后各是多少 | 数字与子项统计 | 子项并列读数，不强调占比；单维度拆分如已处理 10（违规、误报、已忽略），多维度拆分用纵向分割线分组，如终端总数（状态、终端类型） |
| 互斥状态的占比分布如何 | 饼图状态分布 | 状态有颜色语义，需要看分布与健康度，如 PE 运行状态 |
| 哪些对象排前面、多多少 | 横向条形图 TopN | 对象维度排行比较，如 Top5 风险用户 |
| 指标随时间怎么变化 | 曲线趋势图 | 时间维度走势，如近 7 天告警数量 |

补充判断规则：

- 数字与子项统计和饼图状态分布都用于"总数拆分"，按子项性质区分：子项互斥且带状态语义（在线/离线、待激活/在线、成功/失败）优先饼图；只需并列读数、不关心占比优先数字与子项统计；子项超过 5 个不使用饼图，改用数字与子项统计，子项在总项右侧纵排呈现。
- 同一对象可同时计入多个子项（非互斥拆分）时禁用饼图，占比无意义，使用数字与子项统计并在方案中说明口径。
- 需求原文出现"分布、占比、健康度"倾向饼图；出现"Top、排行、最多"倾向条形图；出现"趋势、近 N 天、走势"倾向曲线图；仅出现数字清单倾向纯数字或数字与子项统计。

## 3. 卡片样式详述

单卡片统一使用 `IxCard` 承载。以下线框中数字与名称为示例，按需求替换。

### 3.1 纯数字统计

适用场景：只需一个总量指标且无拆分诉求，例如应用数、资产总数、任务总数。

纯数字统计分两种样式，按同排其他卡片的高度选择：同排存在饼图、条形图、曲线图等高卡片时用纵向样式，以同等高度插图统一概览区高度；同排均为纯数字统计时用水平样式，节约概览区整体高度。同排多张纯数字卡片必须使用同一样式，禁止混用。

样式一：左图右文（纵向），用于与其他高卡片统一高度：

```text
┌──────────────────────────────────────┐
│ ┌────┐   应用数                      │
│ │插图│   80                          │
│ └────┘                               │
└──────────────────────────────────────┘
```

结构：左侧为与卡片内容区等高的插图（示意图形或状态图标）；右侧上方为指标名（小号常规字重），下方为数值（大号加粗，使用 `IxStatistic`），数值可带单位。

样式二：水平排列（图 + 文字 + 数字），用于压低同排纯数字卡片的概览区高度：

```text
┌──────────────────────────────────────┐
│ [插图]   应用数      80              │
└──────────────────────────────────────┘
```

结构：图、指标名、数值从左到右单行排列，垂直居中对齐；指标名小号常规字重，数值大号加粗（使用 `IxStatistic`），数值可带单位。

### 3.2 数字与子项统计

适用场景：一个总量需要按子类拆开读数，例如已处理 10，其中违规、误报、已忽略各多少；也可以是总数下并列多个不同维度的子项统计，例如终端总数 100，状态维度拆为在线、离线、其他，终端类型维度拆为服务器、PC。

```text
┌────────────────────────────┐
│ ┌────┐ 已处理   违规 3     │
│ │插图│ 10    误报 4     │
│ └────┘       已忽略 3    │
└────────────────────────────┘
```

结构：总项参考纯数字统计样式一（数值使用 `IxStatistic`），左侧为等高插图，右侧上指标名、下数值；子项为"子项名 + 数值"的并列小字，统一放在总项右侧，与总项垂直居中。

子项排布取决于卡片宽度：宽度充足时横向排成一行：

```text
┌──────────────────────────────────────────────┐
│ ┌────┐ 已处理  违规 3   误报 4   已忽略 3  │
│ │插图│ 10                                    │
│ └────┘                                       │
└──────────────────────────────────────────────┘
```

卡片宽度不足以放下横排子项时，子项在总项右侧纵向排成一列：

```text
┌────────────────────────────┐
│ ┌────┐ 已处理   违规 3     │
│ │插图│ 10    误报 4     │
│ └────┘       已忽略 3    │
└────────────────────────────┘
```

规则：子项数量通常 2-5 个；按卡片宽度选择横排或纵排，禁止将子项放在总项下方；不做折叠省略；子项之和与总数的关系（互斥合计还是部分口径）必须在方案中说明。

### 3.2.1 多维度子项统计

总数下并列多个不同维度的子项统计时，各维度组在总项右侧从左到右排开，组间用纵向分割线分隔；每个维度组以"维度名 + 该组子项"为整体，组内横排或纵排仍按卡片宽度决定。

```text
┌──────────────────────────────────────────────────────┐
│ ┌────┐ 终端总数   状态          │ 终端类型            │
│ │插图│ 100      在线 70         │ 服务器 10   PC 90  │
│ └────┘          离线 20  其他 10  │                    │
└──────────────────────────────────────────────────────┘
```

规则：每个维度组内各子项之和与总数的关系（互斥合计还是部分口径）必须成立且在方案中说明；维度组数量一般 2～3 个，按实际业务情况决定；维度组过多导致卡片内容过挤或难以阅读时，改用多张卡片分维度呈现；组间仅用一条纵向分割线，组间与组内不叠加第二种分隔样式。

### 3.3 饼图状态分布

适用场景：互斥状态的占比分布，例如 PE 总数 100，运行状态分为待激活、待上线、在线、离线。

```text
┌──────────────────────────────────────┐
│ PE 总数                              │
│      ╭───────╮      ● 在线     62    │
│     │   100   │     ● 离线     21    │
│      ╰───────╯      ● 待激活   12    │
│                      ● 待上线    5   │
└──────────────────────────────────────┘
```

结构：左侧环形图（`IxPieChart`），中心显示指标名与总数；右侧图例纵向排列，每项为"颜色标识 + 状态名 + 数值"，按数量或状态严重程度排序，全站同类卡片排序口径保持一致。

规则：仅用于互斥状态拆分；状态数通常 2-5 个；状态颜色语义与系统内既有状态色保持一致，无既有约定时在方案中列出颜色与状态的映射。

### 3.4 横向条形图 TopN

适用场景：按数值对 N 个对象排行，例如 Top5 风险用户及其关联风险事件数量。

```text
┌──────────────────────────────────────┐
│ Top5 风险用户                        │
│ 张三   ████████████████████ 45       │
│ 李四   ██████████████ 32             │
│ 王五   ██████████ 23                 │
│ 赵六   ██████ 15                     │
│ 孙七   ███ 8                         │
└──────────────────────────────────────┘
```

结构：卡片标题声明 TopN 与指标（如 Top5 风险用户），主体为 `IxBarChart` 横向条形形态；每行为"对象名 + 条形 + 数值"，按数值降序排列，条长按数值占比。

规则：N 默认 5，需求明确时可调整；数据不足以填满 N 时按实际条数展示；对象名过长时截断并加气泡查看完整名称；卡片内仅展示排行与数量，不承载操作入口。

### 3.5 曲线趋势图

适用场景：展示一个指标在一段时间内的变化趋势，例如近 7 天告警数量趋势。

```text
┌──────────────────────────────────────┐
│ 告警数量趋势（近 7 天）              │
│ 45 ┤             ╭──╮                │
│    │   ╭╮       ╱    ╲               │
│    │ ╭─╯ ╰─────╯      ╰─╮            │
│  0 ┼─╯                    ╰──         │
│    └──┬─────┬─────┬─────┬──           │
│     03-01  03-02  03-03  03-04       │
└──────────────────────────────────────┘
```

结构：卡片标题声明指标与时间范围；主体为折线（`IxLineChart`），横轴为时间刻度，纵轴为数值，数值单位在标题或轴中说明。

规则：时间范围与粒度（小时/天/周）由需求确定并写入卡片标题；同一页面多张趋势图的粒度保持一致；曲线图只表达趋势，不承载精确读数诉求，需要精确读数时与纯数字或数字与子项统计组合使用。

## 4. 概览区组合与排序规则

### 4.1 组合数量与布局

- 一排概览卡片不超过 4 张，不允许换行；卡片等分整行宽度，卡片之间间距 8px，卡片高度一致；纯数字统计按 3.1 的样式选择规则与同排卡片高度对齐。
- 概览区放在表格内容卡片上方，位置关系按页面模板执行，不在本节重复定义。
- 卡片数量按信息价值取舍，没有信息增量的指标不单独设卡。
- 每张卡片的数据口径（统计范围、时间范围、是否随筛选变化）必须在方案中说明；未特别说明时默认统计该页面对象的全量数据。

### 4.2 默认排序规则

- 默认按总分结构排序：最左侧为总数卡片，回答"这类对象一共有多少"，通常为纯数字统计或数字与子项统计；从左往右先总后分，维度从概括到具体，例如：对象总数 → 状态分布 → 处置进度 → 趋势或排行。
- 用户从左到右应形成"总量 → 分项 → 细节"的阅读路径，禁止无规则混排。

### 4.3 事件运维场景特例

- 事件运维类页面（告警、事件处置等需要用户认领与处置的场景），把待处理卡片放在最左侧，最需要用户关注和行动的信息优先展示；其后其余卡片仍按总分结构排列。
- 待处理卡片推荐使用数字与子项统计，便于用户按子类分流处置。

组合示例（总分结构，4 卡片等分不换行）：

```text
┌──────────────┐ ┌────────────────────────┐ ┌───────────────────────┐ ┌──────────────────────┐
│ ┌────┐ 设备  │ │ 运行状态分布           │ │ ┌────┐ 已处理  违规 3│ │ Top5 风险用户        │
│ │插图│ 总数  │ │    ╭──────╮ ● 在线  62 │ │ │插图│ 10    误报 4│ │ 张三 ████████████ 45 │
│ │    │ 100   │ │   │  100   │ ● 离线  21 │ │ └────┘      已忽略 3│ │ 李四 █████████ 32    │
│ └────┘       │ │    ╰──────╯ ● 待激活 12│ │                     │ │ 王五 ██████ 23       │
│              │ │            ● 待上线  5 │ │                       │ │ 赵六 ████ 15         │
└──────────────┘ └────────────────────────┘ └───────────────────────┘ └──────────────────────┘
```

排序说明：设备总数 → 状态分布 → 处置进度 → 排行，呈现总分结构；事件运维场景改为待处理卡片置最左，其余不变。设备总数为纯数字统计，因同排存在饼图与条形图，按 3.1 样式一以插图统一高度。

## 5. 输出要求与自检

输出概览区方案时需包含：每张卡片选用的样式与理由（对照第 2 节）、卡片标题与数据口径、子项或扇区或条目清单、组合排序结果（总分结构或事件运维特例）。

输出前逐项检查：

- 每张卡片样式与要回答的问题匹配，未把占比类诉求画成并列数字，未把非互斥拆分画成饼图。
- 饼图仅承载互斥状态且状态数不超过 5 个；曲线图明确时间范围与粒度；条形图按数值降序并声明 TopN。
- 卡片不超过 4 张且不换行，排序呈现总分结构或事件运维待处理优先。
- 纯数字统计按 3.1 规则选择纵向或水平样式，同排多张纯数字卡片未混用样式；数字与子项统计的子项统一在总项右侧，横排或纵排与卡片宽度匹配，未放在总项下方；多维度子项统计的维度组数量按业务实际情况确定（一般 2～3 个）且卡片未过挤，组间用一条纵向分割线分隔。
- 卡片标题声明指标与口径，子项之和与总数的关系已说明。
- 未重复定义页面容器与间距；统计数字与图表组件已按产品实现层规则绑定（`IxStatistic`/`IxPieChart`/`IxBarChart`/`IxLineChart`）。
