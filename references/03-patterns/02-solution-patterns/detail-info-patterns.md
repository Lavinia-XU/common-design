## 1. 文档定位与适用范围

本文档用于指导详情页、详情抽屉和日志详情抽屉中具体信息采用什么展示形式呈现。上游文档 [导航菜单与信息层级拆解](../01-navigation-and-hierarchy.md) 负责"要不要详情页、详情页如何分平铺和Tab、信息如何分层落位"的判断；本文档承接其结论，只负责"每个分区、每个信息块内的信息用什么形式展示"。本文档不做页面类型选择，不做菜单归属判断，也不重复表格和表单的完整规则。

与其他文档的分工边界：

- 是否需要详情页、详情页类型（下钻详情页、详情抽屉、日志详情抽屉）、平铺与Tab切换、信息分层落位：由 [导航菜单与信息层级拆解](../01-navigation-and-hierarchy.md) 判断，本文档不重复。
- 表格自身的工具栏、搜索筛选、字段列、排序、分页、行操作等完整规则：见 [表格与数据管理](table-patterns.md)；本文档只负责判断详情页内一块信息是否适合用表格展示。
- 表单、录入与校验：见 [通用表单设计方法](form-patterns.md)，本文档只覆盖只读展示。
- 组件名称与样式变体编号：按本文档确定展示形式后，组件选型联动 [idux组件映射](../../05-components/idux-component-map.md)（如描述列表用 `IxProDesc`、时间轴用 `IxTimeline`、表格用 `IxProTable`）。

适用对象：详情页主体信息、详情页 Tab 内的独立内容面、详情抽屉与日志详情抽屉的内容区；列表弹窗、概览卡片等只读容器内的信息展示可参照执行。

## 2. 展示形式判断逻辑

确定一块信息放哪之后，按以下决策链选择展示形式，命中即停，按顺序判断：

1. 内容是脚本、JSON、报文、日志原文等原始数据 → 原始内容区块（第 8 节）。
2. 数据之间存在明显的流转、依赖或逻辑关系，需要通过图表达 → 可视化（第 7 节）。
3. 信息是事件、操作、审批等按时间推进的流转记录 → 时间轴（第 6 节）；不满足时间轴条件但仍是历史记录时，退回表格或描述列表。
4. 一组对象各自需要展示不同字段，或需要图标、局部链路等更丰富的表达 → 卡片（第 5 节）。
5. 一组同构对象的数据量大、字段多，或数据持续增长、需要独立成块管理 → 表格（第 4 节）。
6. 字段数量较少、结构固定的主对象属性 → 描述列表（第 3 节）；其中一组重复的轻量数据按 3.2、3.3 用轻量表格或卡片承接。

速查表：

| 信息特征 | 推荐形式 | 关键边界 |
| --- | --- | --- |
| 固定字段的主对象属性，字段少、结构固定 | 描述列表（3.1） | 字段值本身是一组轻量重复数据时，按 3.2 / 3.3 处理 |
| 一组重复数据，字段很少、数据量很小，从属于某个字段 | label加轻量表格（3.2） | 字段多或数据量大时升级为第 4 节独立表格 |
| 一组数据或一组条件，单条字段少但整体需要圈选表达 | label加卡片（3.3） | 需要多个卡片或卡片需丰富视觉表达时，升级为第 5 节独立卡片模块 |
| 数据量大、字段多、需筛选排序分页、数据持续叠加 | 表格（4） | 左树+表格作为详情页内单个内容面时整体一个 Tab 承载 |
| 每张卡片字段不同，或需要图标、局部链路等丰富表达 | 卡片（5） | 卡片多且单卡信息量大时用折叠卡片 |
| 事件流转记录、审批流程，字段只有 2-3 个且数据少、不会持续叠加 | 时间轴（6） | 数据量多或持续叠加时改用表格 |
| 数据之间有明显流转或逻辑关系 | 可视化（7） | 通常独立成块，必要时不与普通信息混排 |
| 脚本、JSON、请求内容、日志原文 | 原始内容区块（8） | 区块内滚动条+复制按钮，代码格式展示 |

判断时先看内容性质（属性、集合、流转记录、关系图、原始数据），再看数据规模与字段结构；同一块内容同时命中多种特征时，按决策链顺序取靠前的形式。

## 3. 描述列表

描述列表是详情页展示主对象属性的基础形式，使用 `IxProDesc` 承载。按字段值的构成分为三种形态。

通用布局规则（三种形态都必须遵守）：label 与 value 水平展示，label 在左、value 在右，位于同一行内；禁止采用 label 在上、value 在下的上下堆叠结构。value 内容过长需要换行时，在同一 value 内向下续行，续行与 value 首字符纵向对齐，label 不重复出现、不换行；3.2、3.3 中 label 与轻量表格、卡片的组合同样遵循水平规则，label 固定在块左侧，表格和卡片从 label 右侧开始排布。

### 3.1 label加纯文本、标签或数字

单条字段用"label + 值"表达，值的形式与表格字段展示形式一致（联动 [表格与数据管理](table-patterns.md#7-表格字段与列设计) 的字段展示形式表：状态用标签、风险等级用深色标签、统计数字用蓝色数字、长文本截断等）。

```text
┌─────────────────────────────────────────────────────┐
│ 基础信息                                             │
│                                                     │
│  名称：xxx策略          状态：● 已启用               │
│  类型：访问控制          优先级：10                  │
│  创建时间：2024-01-01 12:00:00                      │
│  描述：这是一段较长的描述内容，展示不下时换行展示，    │
│        最多三行，超出部分省略号截断，悬浮查看完整...   │
│                                                     │
│  风险等级：[高危]        关联资产：12（蓝色可点击）   │
└─────────────────────────────────────────────────────┘
```

布局与折行规则：

- 根据容器宽度分为 1-2 列；信息较少时用单列，信息较多时用双列。组件识别联动 [idux组件映射](../../05-components/idux-component-map.md)。
- 单个 label 的字段内容较长（如长文本描述、长规则表达式）时，该字段可单独占一行，不强制遵循统一多列，允许多列与单行混排。
- 值展示不完时换行展示，默认最多 2 行、最多 3 行，超出部分省略号截断，提供悬浮或点击查看完整内容的途径（联动 `IxText` 的省略与展开能力）。
- 字段较多时按业务主题增加小标题分组，分组规则按 [导航菜单与信息层级拆解](../01-navigation-and-hierarchy.md#3-信息层级组织) 的信息分层落位执行，本文档不重复。
- 无值统一显示 `-`。

### 3.2 label加轻量表格

某个字段或分区下是一组重复数据（如一组 IP + 运营商、一批端口 + 协议），字段很少、数据量很小，属于字段的从属展开，用轻量表格承接，不套用完整表格页结构。

```text
┌─────────────────────────────────────────────────────┐
│ 网络信息                                             │
│                                                     │
│  IP地址：┌─────────────────┬───────────────┐         │
│          │ IP              │ 运营商        │         │
│          ├─────────────────┼───────────────┤         │
│          │ 10.10.1.1       │ 电信          │         │
│          │ 10.10.1.2       │ 联通          │         │
│          │ 10.10.1.3       │ 移动          │         │
│          └─────────────────┴───────────────┘         │
└─────────────────────────────────────────────────────┘
```

使用约束：

- 仅承接字段很少（通常 2-4 列）、数据量很小（通常 10 条以内）的轻量数据，不承载工具栏、搜索筛选、批量操作和分页。
- 数据超出轻量范围、字段变多或需要独立管理时，升级为独立模块按第 4 节表格展示。
- 不与同分区的其他描述字段强行合并为一列，避免单元格内嵌套过深。

### 3.3 label加卡片

某个字段或分区下是一组数据或一组条件（如一组客户端、一组生效规则、一组规则条件），用一张简单卡片把整组数据包在一个卡片里承接。这里的卡片与 3.2 的轻量表格定位一致，是描述列表字段值的从属形式：卡片只是把一组数据圈在一个容器里，本身不做丰富视觉表达。

```text
┌─────────────────────────────────────────────────────┐
│ 生效客户端：┌───────────────────────────────────┐    │
│             │ Client-A                          │    │
│             │ Windows 11 / 在线                 │    │
│             └───────────────────────────────────┘    │
└─────────────────────────────────────────────────────┘
```

使用约束：

- 本形态表达的是 label 加单个简单卡片：把一组数据用一个卡片包起来整体圈选，label 在左、卡片在右，位于同一行；线框只画 1 个卡片。
- 卡片是轻量简单卡片，主要作用是把一组数据圈在一个容器里，不做丰富视觉表达。
- 出现以下情况之一时，不再使用 label 加单卡片，升级为卡片作为独立模块展示（见 [5. 卡片](#5-卡片)）：需要展示多个卡片；卡片内容需要丰富视觉表达（图标、链路、状态图形等）。

## 4. 表格

详情页内的一块信息是一组同构对象的数据量较大、字段较多的集合（如详情页信息分组或某个 Tab 下的"关联策略"整块内容都是一张表），直接用独立表格模块展示。组件使用 `IxProTable`，表格自身规则全部按 [表格与数据管理](table-patterns.md) 执行，本节只约束详情页内的落位。

```text
┌─────────────────────────────────────────────────────┐
│ 关联策略（信息分组或独立Tab）                          │
│ ┌─────────────────────────────────────────────────┐ │
│ │ [筛选区]                                 [刷新]│ │
│ │ ┌─────────────────────────────────────────────┐ │ │
│ │ │ 策略名称    │ 状态    │ 优先级 │ 操作         │ │ │
│ │ │ policy-01  │ 已启用  │ 10    │ 详情 编辑    │ │ │
│ │ │ policy-02  │ 已禁用  │ 20    │ 详情 编辑    │ │ │
│ │ └─────────────────────────────────────────────┘ │ │
│ │ Pagination（底部）                                │ │
│ └─────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────┘
```

适用判定：

- 该信息分组或 Tab 内的内容全部围绕这一组数据展开，数据量大、字段多或需要筛选、排序、分页、批量操作时使用。
- 与 3.2 的边界：3.2 是字段从属展开的轻量表格；本节是独立成块、按完整表格规则管理的表格。轻量表格一旦出现字段多、数据量大、需要操作管理三种情况之一，即升级为本节形式。

左树+表格的情况：

- 详情页某内容面需要按组织、分组、层级切换数据范围时，使用左树+表格组合（左树用 `IxProTree`，右侧表格按 [表格与数据管理](table-patterns.md) 执行）。
- 作为详情页内的单个内容面时，左树+表格整体作为一个 Tab 或独立模块承载，不再继续嵌套局部 Tab（联动 [导航菜单与信息层级拆解](../01-navigation-and-hierarchy.md#32-信息分层与落位) 的层级落位规则）。
- 左树切换后右侧表格回到第一页并基于当前节点重新请求，搜索筛选受当前节点范围约束。

## 5. 卡片

与表格相比，卡片适合一组对象各自字段不同、或需要更丰富展示形式（图标、局部链路、状态图形等）的集合信息。单个卡片内可以用标签、图标、迷你进度、短链路等元素组合表达。

```text
┌─────────────────────────────────────────────────────┐
│ 检测对象                                             │
│ ┌──────────────────────┐ ┌──────────────────────┐   │
│ │ [icon] 终端A          │ │ [icon] 服务器B       │   │
│ │ Windows 11 / 在线     │ │ CentOS 7 / 告警      │   │
│ │ ─────────────────     │ │ ─────────────────    │   │
│ │ 进程 → 文件 → 网络链路│ │ 进程 → 文件          │   │
│ │ 命中规则：3 条         │ │ 命中规则：7 条        │   │
│ └──────────────────────┘ └──────────────────────┘   │
│ ┌──────────────────────┐                            │
│ │ [icon] 容器C          │                            │
│ │ Ubuntu 20 / 在线      │                            │
│ │ ─────────────────     │                            │
│ │ 进程 → 文件 → 网络链路│                            │
│ │ 命中规则：1 条         │                            │
│ └──────────────────────┘                            │
└─────────────────────────────────────────────────────┘
```

使用约束：

- 适用判定：每张卡片需要展示的字段不同、或卡片内需要图标、局部链路、状态图形等表格无法承载的丰富表达时，用卡片而不是表格。
- 卡片内仍应保持信息密度克制，避免把卡片做成小页面；卡片间结构允许不同，但同一卡片组内的视觉风格保持一致。
- 折叠卡片：卡片数量多且单个卡片信息量比较大时，使用折叠卡片，默认收起次要卡片或折叠卡片详情，避免页面被撑得过长；默认展开数量由业务定义。

```text
折叠卡片形态：
┌─────────────────────────────────────────────────────┐
│ ▼ 检测对象A（展开）                                   │
│ │  Windows 11 / 在线                                 │
│ │  进程 → 文件 → 网络链路  命中规则：3 条              │
│ ├─────────────────────────────────────────────────  │
│ ▶ 检测对象B（收起）                                   │
│ ▶ 检测对象C（收起）                                   │
└─────────────────────────────────────────────────────┘
```

- 卡片组与 3.3 的边界：3.3 是某个字段下的轻量圈选卡片；本节是承载复杂信息的独立卡片模块。
- 与表格的选择：字段同构、需要扫描对比时优先表格；字段异构、需要丰富表达时用卡片。

## 6. 时间轴

纵向时间轴用于展示事件流转记录、审批流程等按时间推进的信息。组件使用 `IxTimeline`（默认轴线居左、内容在右）。

```text
┌─────────────────────────────────────────────────────┐
│ 处置记录                                             │
│  │  2024-01-01 12:00  ● 事件产生                    │
│  │                   │  由系统自动检测产生            │
│  │  2024-01-01 12:05  ● 人工确认                     │
│  │                   │  操作人：张三                  │
│  │  2024-01-01 12:10  ● 处置完成                     │
│  │                   │  操作人：李四                  │
└─────────────────────────────────────────────────────┘
```

与表格的边界，必须同时满足才使用时间轴：

- 展示字段只有 2-3 个（通常为时间、事件名称、操作人或简要结果）。
- 数据量少（通常 10 条以内），一屏可完整浏览。
- 数据不会持续叠加上不封顶（如一次审批、一次处置的固定流转）；数据会持续叠加、条数不可控时改用表格。
- 满足前两条但数据持续叠加、无封顶时，使用表格展示。

其他约束：

- 节点需要表达状态语义（成功、失败、进行中）时，通过节点颜色或图标区分，组件识别联动 [idux组件映射](../../05-components/idux-component-map.md)。
- 内容需要标题加正文段落时，在时间轴节点内组合标题与正文形成内容块，不额外叠加卡片嵌套。

## 7. 可视化

数据之间存在明显的流转、依赖或逻辑关系（进程链、攻击链路、流程图、拓扑关系等），用文本或表格无法直观表达时，使用流程图、进程链等可视化形式展示。这类内容通常需要独立的内容区域承载。

```text
┌─────────────────────────────────────────────────────┐
│ 攻击链路（独立内容区）                                │
│                                                     │
│  ┌────────┐      ┌────────┐      ┌────────┐         │
│  │ 进程    │ ──→ │ 文件    │ ──→ │ 网络    │        │
│  │ cmd.exe │      │ 1.exe  │      │ 外联IP  │        │
│  └────────┘      └────────┘      └────────┘         │
│       │                                  │          │
│       └──────────→ ┌────────┐ ←─────────┘          │
│                    │ 告警    │                      │
│                    └────────┘                      │
└─────────────────────────────────────────────────────┘
```

使用约束：

- 适用判定：信息重点是"关系与流转"而不是"字段值"，需要看节点之间连接关系时使用；只是罗列字段值时不使用可视化。
- 可视化区域通常独立成块；与表格、描述列表等常规信息混排会破坏阅读动线时，独立 Tab 或独立模块承载（落位规则联动 [导航菜单与信息层级拆解](../01-navigation-and-hierarchy.md#312-详情页内信息平铺和tab切换)）。
- 需要复杂视觉效果展示对象信息，是判定需要详情页的信号之一（联动 [导航菜单与信息层级拆解](../01-navigation-and-hierarchy.md#311-判断是否需要详情页)）。
- 可视化组件不在通用组件映射表内时，由业务或技术输入确认实现方式，不得私自假设组件能力。

## 8. 原始内容区块

脚本、JSON、请求内容、日志原文等原始数据，用一个独立的原始内容区块展示。

```text
┌─────────────────────────────────────────────────────┐
│ 请求内容                                  [复制] 📋 │
│ ┌─────────────────────────────────────────────────┐ │
│ │ 1 {                                              │ │
│ │ 2   "id": "evt-001",                            │ ↕
│ │ 3   "level": "high",                            │ │
│ │ 4   "source": "10.10.1.1",                      │ │
│ │ 5   "payload": { "cmd": "curl ..." }            │ │
│ │ ...              （超出高度出现纵向滚动条）         │ │
│ └─────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────┘
```

使用约束：

- 独立区块承载，与普通描述信息分区展示，不与其他展示形式混排在同一容器内。
- 区块内提供纵向滚动条，超出区块高度的内容通过滚动查看，不将页面无限撑长。
- 区块头部提供复制按钮，一键复制完整原始内容；复制内容必须是纯文本。
- 使用专门的代码展示格式（等宽字体、代码高亮），不使用普通文本排版。
- 组件不在通用组件映射表内时，由业务或技术输入确认实现方式；复制能力可联动 `IxText` 的复制能力或等价的组件能力。

## 9. 组合与落位要求

- 一块信息命中且仅命中一种展示形式；同一详情页内多种形式组合时，每种形式各自成块，不互相嵌套替代。
- 块与块的顺序按 [导航菜单与信息层级拆解](../01-navigation-and-hierarchy.md#32-信息分层与落位) 的信息分层落位执行；本文档只负责块内形式。
- 描述列表是详情页基础形式，主对象属性优先用它；集合、流转、关系、原始数据分别按第 4-8 节判断，不要把所有信息都压成描述列表。
- 拆解详情页时，每个信息块要写清"信息特征 → 命中形式 → 关键参数（列数、行数上限、卡片数量等）"，不要只写形式名称。
- 形式判定与实际实现冲突时（如无对应组件、性能限制），保留结论、标注冲突并给出替代建议，交由负责人确认。
