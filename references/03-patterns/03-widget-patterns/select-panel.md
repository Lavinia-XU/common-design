# 下拉选择面板形态与增强

当选择载体已确定为下拉面板时，用本文确定面板内部形态与增强项。载体选择（平铺 Radio、平铺 CheckBox、下拉面板、卡片式选择）见 [通用表单设计方法](../02-solution-patterns/form-patterns.md) 第 6 节；组件选型与样式变体编号见 [idux 组件映射表](../../05-components/idux-component-map.md)。

## 1. 两层模型

下拉面板设计拆成两个互不干扰的层，先定形态，再定增强。

| 层 | 内容 | 关系 | 取值 |
| --- | --- | --- | --- |
| 层 1 面板基础形态 | 面板如何展示选项、如何完成选择 | 互斥，只能选 1 个 | 平铺、平铺+搜索、分组+搜索、树+搜索、级联 |
| 层 2 面板增强项 | 叠加在形态之上的能力 | 正交，可叠加 0-4 个 | 面板内新增、面板确定取消、选项辅助说明、选项禁用原因 |

规则：

- 「搜索」不是独立形态。它是平铺在选项数量超过阈值时的固定升级结果，不作为独立选项参与选择。
- 增强项不改变形态名、不产生新形态。禁止把「带确定按钮的面板」「带新增按钮的面板」当成新的面板形态。
- 形态与单选、多选正交：形态决定展示结构与选择路径，单选或多选由字段语义决定，不改变形态。
- 输出时按「形态 + 增强项」书写，例如「平铺+搜索 + 确定取消 + 面板内新增」。禁止自造形态名，如「搜索多选」「树级联」。

### 1.1 形态与增强 ID

| 类型 | ID | 名称 |
| --- | --- | --- |
| 形态 | `panel-flat` | 平铺 |
| 形态 | `panel-flat-search` | 平铺+搜索 |
| 形态 | `panel-group-search` | 分组+搜索 |
| 形态 | `panel-tree-search` | 树+搜索 |
| 形态 | `panel-cascader` | 级联 |
| 增强 | `panel-enhance-create` | 面板内新增 |
| 增强 | `panel-enhance-confirm` | 面板确定取消 |
| 增强 | `panel-enhance-helper` | 选项辅助说明 |
| 增强 | `panel-enhance-disabled-reason` | 选项禁用原因 |

## 2. 面板基础形态

### 2.1 形态判定链

先判断层级与分组，再决定平铺是否带搜索：树与级联看选项本身的语义特征，分组看需求是否对选项进行了分组描述。整个判定分两步，命中即止；顺序本身即互斥规则，命中高优先级后不得再叠加低优先级的形态特征。

#### 第一步：选项是否存在明显的层级或分组特征

逐行核对，命中即止。树与级联依据选项语义特征判断；分组依据需求是否对选项进行了分组描述判断。命中前四种之一时直接定形态，数量不再改变形态，只决定是否附带搜索框。

| 特征类型 | 判断特征 | 形态 | 形态 ID | 组件 |
| --- | --- | --- | --- | --- |
| 组织型层级 | 数据本身是组织架构、部门、设备组、资产组、目录树等业务层级结构，父子节点可独立选中（选父不等于默认选中全部子） | 树+搜索 | `panel-tree-search` | `IxTreeSelect` |
| 隶属型层级 | 层级之间是唯一确定的隶属关系，必须从根到叶逐级选择才能定位，如国家-省-市-区县 | 级联 | `panel-cascader` | `IxCascader` |
| 需求分组描述 | 需求里对选项进行了分组描述（给出了分组标题或分组归属），且选项不符合前两行的组织型层级与隶属型层级特征，即排除树和级联 | 分组+搜索 | `panel-group-search` | `IxSelect` + `type: 'expandableGroup'` |
| 无明显层级与分组 | 需求未对选项分组描述，选项只是一组平行选项，最多存在一层分类维度（按类型、来源、状态归类） | 进入第二步 | 按第二步数量决定平铺是否带搜索 | `IxSelect` |

树与级联的判断依据是选项之间的归属关系；分组的判断依据是需求有没有对选项进行分组描述。需求只给出选项名、未描述分组时，不使用分组形态，按第二步判定。

#### 第二步：平铺时是否附带搜索框

选项之间无明显层级与分组特征时使用平铺，平铺是否带搜索框由选项数量决定：

| 顺序 | 选项数量 | 形态 | 形态 ID | 组件 |
| --- | --- | --- | --- | --- |
| 1 | 10 个及以内 | 平铺 | `panel-flat` | `IxSelect` |
| 2 | 超过 10 个 | 平铺+搜索 | `panel-flat-search` | `IxSelect`（必须带搜索框） |

判定说明：

- 层级与分组优先于数量：选项存在明显层级或分组特征时先按第一步定为分组、树或级联，不因为数量少而降级为平铺。
- 搜索阈值：平铺超过 10 个必须带搜索框；分组、树与级联形态自带搜索框，不因数量少而省略。
- 级联对层级要求最高：层级之间没有明确且唯一的归属关系时不要使用级联，否则用户难以定位；组织型层级或父子可独立选中时优先用树。
- 级联最多 3 层、默认 2 层；只有「国家-省-市-区县」这类有明确行政或组织隶属关系的数据可按实际层数，超出 3 层前先确认需求是否真的需要逐级选择。
- 分组是需求驱动的：需求对选项进行了分组描述且排除树与级联时，直接命中第一步的分组+搜索，不进入第二步按数量定平铺；需求未描述分组时回到第二步按数量判定。
- 数量只是触发条件之一：选项名称长、相似度高时，即使未超阈值也可以提前使用平铺+搜索。
- 选项数量按业务常见规模估算：有明显增长预期时按增长后的规模判断，避免后续从平铺升级为平铺+搜索。

### 2.2 平铺（`panel-flat`）

```text
┌────────────────────────┐
│ 选项 A                 │
│ 选项 B                 │
│ 选项 C                 │
└────────────────────────┘
```

- 适用：选项之间无明显层级关系，数量 10 个及以内且结构单一。
- 要求：选项高度一致，不出现层级缩进与层级结构；多选使用 `multiple`。
- 禁止：少量选项强行开启搜索；为凑数量制造层级结构。

### 2.3 平铺+搜索（`panel-flat-search`）

```text
┌────────────────────────┐
│ [搜索输入框]           │
├────────────────────────┤
│ 选项 A                 │
│ 选项 B                 │
│ ...                    │
└────────────────────────┘
```

- 适用：单层结构，选项超过 10 个；或数量未超阈值但选项名称长、相似度高，用户需要按名称快速定位。
- 要求：搜索框固定在面板顶部；只匹配选项名称，必要时附带编码等辅助标识。
- 禁止：无搜索需求时保留搜索框；搜索结果重新排序导致选项位置跳变。

### 2.4 分组+搜索（`panel-group-search`）

```text
┌────────────────────────┐
│ [搜索输入框]           │
├────────────────────────┤
│ ▼ 访问主体             │
│    源IP                │
│    源区域              │
│    源国家              │
│    应用账号            │
│    组织架构            │
│ ▼ 访问应用             │
│    应用名称            │
│    目的IP              │
│    目的端口            │
│    HOST                │
└────────────────────────┘
```

- 适用：需求对选项进行了分组描述（给出分组标题或分组归属），且选项不符合组织型层级与隶属型层级特征，即排除树和级联。
- 要求：命中即默认使用分组+搜索；分组标题只作导航、不可选中；分组可展开收起；搜索命中时展开包含命中项的分组，并保留分组标题上下文。
- 禁止：需求未对选项分组描述时按语义或数量推测强行分组（回到第二步按数量判定）；分组内部再嵌套层级（需层级时改用树）。

### 2.5 树+搜索（`panel-tree-search`）

```text
┌────────────────────────┐
│ [搜索输入框]           │
├────────────────────────┤
│ ▼ 组织 A               │
│    ├ 设备组 A1         │
│    └ 设备组 A2         │
│ ▶ 组织 B               │
└────────────────────────┘
```

- 适用：选项存在明显的组织型层级（2 层及以上），父子节点可独立选中（选父不等于默认选中全部子）；层级优先于数量，数量无上限，可持续拓展。
- 常见场景：选择组织架构、设备组、资产组等具有业务层级结构的数据时，默认使用树承载。
- 要求：明确默认展开层级；多选时处理父节点半选态与提交值的关系；搜索命中时展开命中路径并高亮命中节点。
- 禁止：与级联混用（逐级依赖场景改用 `panel-cascader`）；用 `IxProTree` 承担表单内树选择；搜索后丢失层级归属。

### 2.6 级联（`panel-cascader`）

```text
┌──────────┬──────────┬──────────┐
│ 一级     │ 二级     │ 三级     │
│ 组织 A   │ 设备组 A1│ 设备 A-01│
│ 组织 B > │ 设备组 A2│ 设备 A-02│
└──────────┴──────────┴──────────┘
```

- 适用：层级之间存在明确且唯一确定的隶属关系、选择路径逐级依赖，必须从根到叶逐级选择后才能提交，如国家-省-市-区县；常见规模 20-100 个，层级特征优先于数量判断。
- 要求：明确层级数量（默认 2 层、最多 3 层，有明确隶属关系的数据除外）、默认展开层级、选中值结构与提交格式；面板内必须支持关键字搜索；多选时注意 `fullPath` 开启后的值类型差异。
- 禁止：用多个 `IxSelect` 手工拼接级联；父级与子级同时平铺展示导致用户可跳级选择；只展示层级而未同步选中值结构；层级之间没有明确归属关系时使用级联（应改用树）；超过 3 层仍用级联。

## 3. 面板增强项

### 3.1 增强项清单

| 增强项 ID | 名称 | 触发信号 | 组件能力 | 实现要求 | 约束 |
| --- | --- | --- | --- | --- | --- |
| `panel-enhance-create` | 面板内新增 | 候选项来自可维护数据源，且业务允许在面板内直接新建 | `allowInput`；或面板底部「新增 XX」入口配合 `overlayRender` | 明确新增校验（重名、长度、格式、数量上限）；新增成功后写入数据源并自动选中；新增入口文案使用具体对象名，如「新增标签」 | 树与级联仅允许在末级新增；不在分组标题与父节点上提供新增 |
| `panel-enhance-confirm` | 面板确定取消 | 多选且需要「选完再生效」，或选择会触发较重联动 | `needConfirm` | 面板底部提供「确定」「取消」；确定后统一提交已选值，取消后回滚到打开面板前的值；未确认时面板外点击不提交 | 默认仅多选使用；单选默认即选即生效，业务显式要求时才例外 |
| `panel-enhance-helper` | 选项辅助说明 | 选项之间的差异需要用文字解释（效果、适用范围、风险） | 选项内第二行说明文本 | 说明随选项行展示，文本简短；不参与搜索匹配 | 说明过长时下沉为字段说明、帮助链接或模块说明，不在面板内堆大段文案 |
| `panel-enhance-disabled-reason` | 选项禁用原因 | 部分选项因权限、状态或前置条件不满足而不可选 | 选项禁用态 + 原因文案 | 禁用原因必须与禁用逻辑一致；原因文案随选项展示或悬停展示完整内容；面板内提供统一的禁用原因表达方式 | 禁用项不参与全选、不参与搜索结果选中；禁止静默禁用（选项不可选却无原因） |

### 3.2 兼容矩阵

| 形态 \ 增强 | 面板内新增 | 确定取消 | 辅助说明 | 禁用原因 |
| --- | --- | --- | --- | --- |
| 平铺 | 允许 | 多选允许 | 允许 | 允许 |
| 平铺+搜索 | 允许 | 多选允许 | 允许 | 允许 |
| 分组+搜索 | 允许 | 多选允许 | 允许 | 允许 |
| 树+搜索 | 仅末级 | 允许 | 允许 | 允许 |
| 级联 | 仅末级 | 允许 | 建议仅末级开启 | 允许 |

组合约束：

- 增强项之间没有冲突，只受上表与各增强项约束限制。
- 出现约束冲突时，先保留形态判定结果，再对增强项降级，并在设计说明中写明降级原因。

「平铺+搜索 + 面板内新增 + 确定取消 + 辅助说明 + 禁用原因」：


## 4. 交互契约

- 生效时机：未叠加确定取消增强时，选中即生效；叠加后以「确定」为界，「取消」回滚到打开面板前的值。
- 搜索匹配范围：只匹配选项名称，必要时匹配编码等辅助标识；辅助说明、禁用原因不参与匹配。
- 搜索无结果：展示「无匹配结果」；存在面板内新增增强时，同时展示新增入口作为出口。
- 新增：校验通过后写入数据源并自动选中；校验失败时保持面板打开并给出失败原因。
- 多选回显：选择器内以标签形式回显；超过 2 个折叠为「已选 N 项」，避免撑开表单。
- 禁用项：保持可见并展示原因，不参与全选，也不能通过搜索批量选中。
- 空数据：数据源为空时展示空状态；存在新增增强时以新增作为空状态出口。
- 与筛选区共存：查询区筛选项默认即选即生效，不叠加确定取消增强。

## 5. 输出结构与自检清单

输出下拉面板设计时，按以下结构书写：形态与形态 ID、形态判定依据、增强项清单与 ID、面板线框、交互契约要点。

自检清单：

- 形态唯一：只选择了 1 个形态，未把搜索或增强项写成形态。
- 判定链一致：形态与判定链优先级一致；逐级依赖场景未使用树。
- 判定依据来源：写明该形态的判定依据——组织型层级用树、隶属型层级用级联（依据选项语义）；需求分组描述且排除树与级联时用分组+搜索（依据需求描述）；无明显特征时按数量推断平铺形态。
- 增强合规：所有增强项落在兼容矩阵内；树、级联的新增仅出现在末级。
- 组件一致：形态与组件映射一致，分组+搜索使用 `IxSelect` 的 `expandableGroup`，树使用 `IxTreeSelect`，级联使用 `IxCascader`。
- 生效时机明确：写明即选即生效或确定后生效。
- 边界明确：写明辅助说明与禁用原因不参与搜索匹配，禁用项不参与全选。
- 写法规范：按「形态 + 增强项」书写，未自造形态名。
