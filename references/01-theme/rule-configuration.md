# 规则配置主题设计模板

## 适用场景
- 用于配置和管理多条“命中指定条件即按规则处置”的规则集合。
- 适用于告警规则、白名单规则、黑名单规则、放行规则、封禁规则、检测规则等场景。
- 常见需求表达包括规则配置、规则管理、告警规则、白名单规则、黑名单规则、条件配置、命中条件、生效对象等。
- 核心特征：
  - 需要维护多条规则；是否支持优先级与移动排序以需求为准：需求未要求执行顺序时规则相互独立，存在“多条同时命中须确定先后”的需求时规则同样提供优先级与移动排序。
  - 每条规则必须包含条件配置，条件是本主题的核心配置对象。
  - 规则的处置动作由规则类型决定或较为固定，例如告警规则命中后告警、白名单规则命中后放行，一般不需要逐条配置复杂的执行动作。
- 核心目标是将规则抽象为：
  - 规则条件：满足什么条件时该规则命中。
  - 生效范围：规则作用于哪些对象。
  - 规则状态：规则是否启用以参与匹配。
- 常见业务流程：管理员创建规则 → 配置命中条件 → 设置生效范围 → 启用规则 → 系统对范围内的对象按条件匹配并执行规则对应处置。

## 与策略管理主题的关系形态

规则配置与策略管理都可能出现“规则”字样，两者不是按名称二选一，而是按需求场景判断。判定分三步：

- 第 1 步 看执行顺序需求：多条规则或策略同时命中时，是否需要确定执行先后？
  - 需要 → 无论叫规则还是策略，都要支持优先级与移动排序，不要默认规则没有优先级；不需要 → 列表顺序仅作展示，无优先级概念。
- 第 2 步 看是否存在策略引用规则：需求是否同时存在“规则管理列表”与“策略/引用列表”，由策略列表引用已配置好的规则？
  - 是 → 按类型 C 处理，生效对象上移到策略层；否 → 规则自包含生效对象，按类型 A 或 B 处理。
- 第 3 步 看需求场景：是相互独立的规则集合，还是带默认策略与完整动作的策略体系。

按需求场景划分为三种类型：

- 类型 A：独立规则集（本主题默认场景）。需求为告警规则、白名单规则、黑名单规则、检测规则等独立规则集合；规则自包含条件配置、生效对象与状态；需求未要求执行顺序时规则相互独立，存在按序执行需求时同样支持优先级与移动。
- 类型 B：策略体系（配合读取策略管理主题）。需求为访问控制、防火墙、审计管控等完整策略体系，存在优先级、移动排序、默认策略与完整执行动作。
- 类型 C：规则库 + 策略引用（本主题与策略管理主题配合使用）。规则较复杂需要单独维护、灵活性要求高时，需求会同时存在规则管理列表与策略管理列表：策略列表引用已配置的规则并决定“对谁生效”，规则层不配置生效对象；此类规则通常仍有优先级与移动（按第 1 步判断是否保留）。

| 判断维度 | 类型 A 独立规则集 | 类型 B 策略体系 | 类型 C 规则库+策略引用 |
|---|---|---|---|
| 需求形态 | 告警规则、白名单规则等独立规则集合 | 访问控制、防火墙、审计管控等完整策略体系 | 复杂规则单独维护，策略列表引用规则 |
| 核心配置 | 条件配置为核心，动作固定或由规则类型决定 | 条件、执行动作、生效时间完整配置 | 规则层配置条件，策略层决定引用哪些规则 |
| 优先级与移动 | 默认无；需求要求按序执行时同样支持 | 存在，多条同时匹配按优先级执行 | 通常存在，按执行顺序需求判断 |
| 生效对象配置位置 | 规则自身 | 策略自身 | 上移到策略层，规则层不配置 |
| 特殊对象 | 一般无默认规则 | 常存在只读且固定在最后的默认策略 | 一般无 |
| 主要操作 | 新增、删除、启用、禁用、导入、导出 | 在以上基础上增加移动排序、优先级调整 | 规则层同类型 A；策略层同类型 B |

- 完整策略体系（类型 B）或策略引用规则（类型 C）需求时，配合读取 [策略管理主题设计模板](./strategy-management.md)。
- 需求只是维护多条带条件配置的规则且无上层策略引用（类型 A）时，使用本模板。

## 常见页面组合
| 页面ID | 页面名称 | 页面类型 | 页面用途 | 入口方式 | 关键交互 | 设计来源 |
|---|---|---|---|---|---|---|
| P001 | 规则列表页 | 基础表格页 | 查看、筛选、排序、管理已有规则 | 独立菜单入口或业务模块入口 | 点击新增或编辑按钮打开P002；点击规则名称打开P002并带入已有数据；支持删除、启用、禁用、导入、导出 | 通用设计 |
| P002 | 新增/编辑规则页 | 弹窗表单页 | 创建或编辑规则基础信息、条件配置和生效范围 | 列表页新增按钮、编辑按钮、规则名称链接 | 新增为空数据，编辑带入已有数据；校验通过后保存并返回P001 | 通用设计 |

### 页面组合说明
- 新增、编辑通常复用同一个弹窗：新增时表单为空数据，编辑时带入已有数据；一般不单独设计“查看”按钮，点击规则名称打开编辑弹窗并带入已有数据即可完成查看；无编辑权限时弹窗内字段禁用且不可修改。
- 规则条件复杂或需要可视化调试命中效果时，可按业务需要扩展独立规则详情页或命中测试能力；默认页面组合不引入，保持“列表 + 弹窗”的最小形态。
- 规则数量很大（例如白名单规则上千条）时，以批量导入为主要录入方式，弹窗新增用于少量补充，此时列表的空状态和批量操作反馈尤为重要。
- 规则列表的通用表格交互（工具栏按钮状态、勾选数量限制、批量操作反馈、字段展示、排序、分页与刷新规则）统一遵循 [表格规范](../04-patterns/02-table-patterns.md)，本主题只补充规则场景的字段与交互差异。

## 页面设计要点

### P001-规则列表页
- 页面类型：基础表格页。
- 页面类型 ID：`page-table-basic`。
- 页面目标：让管理员集中查看规则、定位目标规则、批量维护规则状态，并完成规则的新增、删除、启用、禁用、导入、导出。
- 页面内容区块：只有一个表格，左上方是按钮区，右上方是筛选搜索区。

#### 页面线框
```text
┌──────────┬───────────────────────────────────────────────────┐
│          │ 页面标题栏：告警规则 / 白名单规则                  │
│  左侧    ├───────────────────────────────────────────────────┤
│  深色    │ ↓ 间距 8px                                        │
│  导航    │ ┌─────────────────────────────────────────────┐  │
│          │ │ 新增 删除 启用 禁用 导入 导出 │ 状态 生效对象 搜索 │ │
│          │ ├─────────────────────────────────────────────┤  │
│          │ │ 序号 | 规则名称 | 规则ID | 规则描述 | 规则内容   │ │
│          │ │ 生效对象 | 状态 | 创建时间 | 更新时间 | 操作    │ │
│          │ │                                             │  │
│          │ │ Pagination（吸附底部）                       │  │
│          │ └─────────────────────────────────────────────┘  │
└──────────┴───────────────────────────────────────────────────┘
```

#### 组件信息
- 页面标题：使用 `IxHeader`。
- 操作按钮：使用 `IxButton`；新增按钮放在表格工具栏左侧首位。
- 筛选搜索：状态筛选使用 `IxSelect`，生效对象筛选使用 `IxSelect` 或搜索选择器，关键字搜索放在筛选区末尾使用 `IxInput`。
- 表格与分页：使用 `IxProTable` 和 `IxPagination`。
- 状态标记：使用 `IxTag`。

#### 按钮区
| 名称 | 用途 | 交互说明 |
|---|---|---|
| 新增 | 创建新的规则 | 点击后打开P002新增弹窗。 |
| 删除 | 批量删除规则 | 需要勾选至少一个对象后激活；点击删除后弹出二次确认，告知删除后规则不再生效；确认后删除所选规则。 |
| 启用 | 批量启用规则 | 需要勾选至少一个对象后激活；点击启用后需要二次确认，告知会立即参与匹配；状态从禁用切换为启用，已启用的规则跳过。 |
| 禁用 | 批量禁用规则 | 需要勾选至少一个对象后激活；点击禁用后规则停止参与匹配；状态从启用切换为禁用，已禁用的规则跳过。 |
| 导入 | 批量导入规则 | 交互方式参考 [导入功能点设计模板](../02-feature/import.md)，结合规则字段和条件配置定义模板与校验规则。 |
| 导出 | 批量导出规则 | 交互方式参考 [导出功能点设计模板](../02-feature/export.md)，支持按全部规则、当前筛选结果或勾选规则导出。 |

#### 筛选搜索区
- 常见筛选项：规则名称、规则ID、规则描述、状态、生效对象、创建时间、更新时间。
- 状态筛选：使用下拉单选，选项为启用、禁用。
- 生效对象筛选：使用下拉单选或搜索选择器，选项来自生效对象类型。
- 搜索建议：关键字搜索框放在筛选区最后，同时支持按规则名称、规则ID、规则描述匹配；业务明确时也可支持按规则内容关键字匹配。
- 筛选形式：普通条件使用搜索框加选择框平铺展示；加入创建时间、更新时间范围后条件超过 4 个时升级为高级搜索组件。
- 筛选联动：状态筛选应与启用、禁用操作后的列表状态同步更新；生效对象筛选与规则编辑后的生效范围变化保持一致。

#### 表格区
| 字段 | 展示形式 | 组件名称 | 说明 |
|---|---|---|---|
| 序号 | 文本/数字 | `IxText` | 展示行号或规则创建顺序，用于辅助定位；规则数量大或已有规则ID作为识别时可不展示。 |
| 规则名称 | 链接文本 | `IxText` | 唯一标识规则；点击后打开P002编辑弹窗并带入已有数据。 |
| 规则ID | 等宽文本 | `IxText` | 系统生成的唯一标识，只读；用于检索和定位，支持复制。 |
| 规则描述 | 文本 | `IxText` | 补充规则用途；长文本省略并支持气泡查看。 |
| 规则内容 | 文本摘要/标签 | `IxText` / `IxTag` | 展示条件配置的可读化摘要，例如“风险等级=高危 且 源IP属于10.0.0.0/8”；超长省略并支持气泡查看；条件涉及的关键枚举可用标签辅助展示。 |
| 生效对象 | 标签/文本/数量链接 | `IxTag` / `IxText` | 展示生效对象范围，例如资产分组、用户组、IP段、域名；对象较多时折叠展示并支持查看明细。 |
| 状态 | 状态标签 | `IxTag` | 展示启用或禁用；启用表示规则参与匹配，禁用表示停止匹配。 |
| 创建时间 | 时间 | `IxText` | 展示规则创建时间。 |
| 更新时间 | 时间 | `IxText` | 展示规则最近更新时间。 |
| 操作 | 操作按钮 | `IxButton` | 编辑、复制、删除；三个操作直接展示，操作列固定右侧，不随横向滚动移动。 |

#### 关键交互
- 新增：点击后打开P002新增弹窗；保存成功后关闭弹窗并刷新列表，默认回到第一页，新规则按创建时间从近到远排在第一条。
- 编辑：点击行内编辑或规则名称后打开P002编辑弹窗；保存成功后关闭弹窗并刷新该行内容。
- 复制：复制当前规则的条件配置和生效范围生成一条新规则，规则名称默认追加“-副本”，规则ID由系统重新生成；复制后的规则建议默认置为禁用，由用户确认配置无误后再启用，避免复制即生效。
- 删除：单行删除和批量删除都必须二次确认，确认文案需提示删除后规则不再生效。
- 启用/禁用：操作前提示状态影响，启用提示规则将立即参与匹配，禁用提示规则将停止匹配；操作成功后状态标签和筛选结果同步更新。
- 查看：一般不单独提供查看按钮；点击规则名称打开P002并带入已有数据即可查看，无编辑权限时字段禁用。

#### 状态与边界
- 未选择任何规则时，批量删除、启用、禁用按钮置灰或点击后提示“请先选择规则”。
- 空列表时展示创建或导入引导，保留新增和导入入口。
- 搜索无结果时展示无结果提示，保留重置筛选入口。
- 启用的规则条件配置或生效范围不完整时，应提示无法启用并引导编辑补全。
- 编辑已启用规则时，如果修改会立即改变线上匹配行为，点击确定前应提示变更影响。
- 删除、禁用、导入等操作失败时，保留当前列表状态并给出失败原因。
- 长规则名称、长描述、规则内容摘要过长或生效对象过多时使用省略、气泡或折叠标签展示。
- 默认排序：规则数量多或页面无既有排序时，默认按创建时间从近到远排序，新增规则排在第一条；具体见 [表格规范-排序](../04-patterns/02-table-patterns.md#8-排序)。

### P002-新增/编辑规则页
- 页面类型：弹窗表单页。
- 页面类型 ID：`page-form-modal`。
- 页面目标：创建新的规则，或编辑已有规则的基础信息、条件配置和生效范围；没有编辑权限时，用同一弹窗承载查看需求。
- 入口方式：从P001规则列表页的新增按钮、编辑按钮、规则名称链接进入。
- 返回方式：点击确定、取消或关闭按钮返回P001。

#### 页面线框
```text
┌──────────────────────────────────────────────────────────────┐
│ 标题栏：新增/编辑规则                              关闭 ×    │
├──────────────────────────────────────────────────────────────┤
│ 规则名称    [____________________________]                   │
│ 规则描述    [____________________________]                   │
│ 状态        (•) 启用  ( ) 禁用                               │
│ 条件配置                                                      │
│      ┌────────────────────────────────────────────────────┐   │
│ ┌且┐ │ [源IP ▼]     [等于 ▼]     [1.1.1.1]       [×]      │   │
│ └┬─┘ ├────────────────────────────────────────────────────┤   │
│  │   │ [目的端口 ▼] [等于 ▼]   [80]             [×]      │   │
│  │   └────────────────────────────────────────────────────┘   │
│  └─────── [+ 添加条件]                                        │
│ 生效范围    [选择生效对象            ▼]                      │
│                                                              │
├──────────────────────────────────────────────────────────────┤
│                                                [确定] [取消] │
│                         底部按钮栏                           │
└──────────────────────────────────────────────────────────────┘
```

线框说明：上图弹窗中的条件配置区按“可动态增删的条件列表”形态（形态二）示意。两条条件组成一组，组前以竖线连接各条件行，竖线上放置正方形色块，色块内文字“且/或”标识该组条件的关系，色块紧贴条件行左缘并位于竖线上端，垂直位置与组内第一行条件的组件行水平对齐，而非与“条件配置”标签行对齐；存在多个条件组时，每组前分别用竖线加色块标记。当需求为固定字段的普通表单形态（形态一）时，该区域改为普通表单字段平铺，不出现组前竖线、“且/或”色块、“添加条件”按钮和行尾删除 icon。

#### 组件信息
- 页面容器：使用 `IxProFormModal`。
- 表单字段：规则名称使用 `IxInput`，规则描述使用 `IxInput`，状态使用 `IxRadioGroup`（单选组，启用/禁用两个选项同时展示）。
- 条件配置：先按需求选择形态——固定字段形态下条件字段直接按语义映射为 `IxInput`、`IxSelect` 等普通表单控件；动态条件列表形态下使用 `IxProFormList`，每个条件一行、一行三个组件水平排列：匹配对象选择框（`IxSelect`）、操作符选择框（`IxSelect`）、条件值控件（按匹配对象属性映射为 `IxSelect`、`IxInput` 或 `IxTextarea`），行尾删除 icon 与列表下方“添加条件”按钮使用 `IxButton`；组内逻辑关系不使用下拉或单选控件，而是在组前竖线上放置正方形色块，色块内以“且/或”文字标识，色块紧贴条件行左缘并位于竖线上端，垂直位置与组内第一行条件的组件行水平对齐，而非与“条件配置”标签行对齐。
- 生效范围：使用 `IxSelect` 或对象选择器，按生效对象类型选择对应选择器。
- 底部操作：取消、确定按钮使用 `IxButton`，按弹窗表单页的底部操作区规则对齐；表单通用校验与布局细节遵循 [表单规范](../04-patterns/03-form-patterns.md)。

#### 表单区
| 字段 | 展示形式 | 组件名称 | 说明 |
|---|---|---|---|
| 规则名称 | 输入框 | `IxInput` | 必填；用于唯一标识规则，需校验重名和长度。 |
| 规则描述 | 输入框 | `IxInput` | 非必填；说明规则用途、适用场景或注意事项。 |
| 状态 | 单选组 | `IxRadioGroup` | 必填；使用 `IxRadioGroup` 单选组，组内同时展示“启用”“禁用”两个选项供直接切换；新增时默认选中“启用”。 |
| 条件配置 | 普通表单字段，或条件行列表 + 组前且/或色块 | 按形态映射字段组件；动态列表形态用 `IxProFormList` | 必填；固定字段形态按字段平铺配置；动态列表形态需至少一条完整条件，组前竖线色块标识且/或关系。 |
| 生效范围 | 对象选择器 | `IxSelect` 或未在组件映射表定义的对象选择器 | 必填；定义规则作用于哪些对象，例如资产分组、用户组、IP段、域名。 |

#### 条件配置
条件配置是规则配置主题的核心表单区。先按需求判断配置形态，再按对应规则设计，不要默认所有规则的条件都必须用动态条件列表配置：

**形态一：固定字段的普通表单**
- 需求没有要求多条同类条件动态增删，或条件字段固定、数量固定时使用，例如规则只需配置“源地址、目的地址、协议”等固定字段。
- 条件字段直接作为普通表单字段平铺展示，组件按字段语义映射为输入框、选择框等，不引入动态列表和逻辑关系；布局与校验遵循 [表单规范](../04-patterns/03-form-patterns.md)。

**形态二：可动态增删的条件列表（仅当需求为这种形态时使用）**
- 需求表现为“维护多条同类条件，每条由匹配对象、操作符、条件值组成，支持添加删除，多条条件之间以组前色块标识且/或关系”时使用，例如告警规则需要配置多条“源IP 等于 10.0.0.1”类的条件行；P002 线框中的条件配置区即按此形态示意。该形态设计规则如下：
- 条件配置使用 `IxProFormList` 动态表单列表呈现：三个组件一行组成一条条件，默认给出一行空条件；列表下方提供“添加条件”按钮，点击后在已有条件下方追加新的一行，重复“选择对象 → 选择操作符 → 填写条件值”的行为。
- 一行中第一个组件是选择框，用于选择匹配对象，例如源IP、目的IP、源端口、目的端口、域名等；匹配对象表示“条件针对哪个属性”，与生效范围中“规则作用于哪些对象（资产分组、用户组等）”含义不同，两者不要混用。
- 第二个组件是选择框，用于选择操作符，例如等于、不等于、包含、不包含；按匹配对象属性可扩展属于、不属于、大于、小于、在范围内等操作符。
- 第三个组件是条件值控件，形式取决于第一个组件所选对象的属性：枚举类属性用选择框，短文本用基础输入框，长文本用多行输入框；需要时支持多选、IP段输入、时间范围选择器；切换匹配对象或操作符后，第三个组件联动切换。
- 同一行内三组件联动：匹配对象决定可选操作符集合，操作符决定条件值控件形式；三个组件共同构成一条完整的条件记录。
- 多条条件组成一组时，组前以竖线连接各条件行，竖线上放置正方形色块，色块内文字“且/或”标识该组条件的关系，色块紧贴条件行左缘并位于竖线上端，垂直位置与组内第一行条件的组件行水平对齐，而非与“条件配置”标签行对齐；存在多个条件组时，每组前分别以竖线加色块标记，组间关系按业务语义确定。
- 每一行右侧提供删除 icon，点击后删除该行条件；条件列表至少保留一条条件，不允许删除到空。
- 条件行中任一组件为空（未选择匹配对象、未选择操作符或条件值为空）时不允许保存和启用，对应行给出字段级错误；已启用规则若条件被改坏，保存前必须提示并阻止。

#### 底部操作
- 确定：校验规则名称、条件配置完整性和生效范围；校验通过后保存并返回P001。
- 取消：未修改时直接关闭；已修改时提示未保存内容。
- 关闭：逻辑同取消。

#### 状态与边界
- 规则名称为空、重名或超过长度限制时，给出字段级错误。
- 条件配置为空、条件行不完整或条件值缺失时，不允许保存或不允许启用。
- 生效范围为空时不允许保存或不允许启用。
- 编辑已启用规则时，若修改会立即影响线上匹配行为，点击确定前应提示变更风险。
- 条件行较多或规则内容复杂时，弹窗内容应支持滚动或分组展示，避免表单过长难以操作。
- 无编辑权限时弹窗内字段禁用且不可修改，仅可查看。

## Coding提示
- 推荐复用组件：基础表格、批量操作工具栏、搜索筛选、状态标签、二次确认弹窗、弹窗表单、对象选择器、条件配置器。
- Mock数据要求：覆盖启用、禁用、不同规则类型、多条件组合（且/或）、长规则名称、长描述、条件摘要超长、多生效对象、无生效对象、创建时间和更新时间差异等数据。
- 状态联动：新增、编辑、删除、复制、启用、禁用、导入后，列表数据、状态标签、筛选结果、空状态和默认排序需要同步变化；新增规则必须按创建时间从近到远出现在第一条。
- 条件数据结构：Mock与接口设计中条件配置建议按“组关系（且/或）+ 条件数组（匹配对象、操作符、条件值）”结构化存储，便于列表展示可读化摘要和导入导出。
- 极端情况：条件值为空、条件组合不合法、规则名称重复、复制后名称超长、已启用规则被编辑、批量操作中部分规则状态不一致、导入数据字段缺失或条件格式错误等。
- 导入/导出关联：如需求明确包含导入，读取 [导入功能点设计模板](../02-feature/import.md)，在页面说明中明确文件选择、模板下载、解析校验、导入结果和失败明细，导入模板需包含条件配置的结构化表达；如需求明确包含导出，读取 [导出功能点设计模板](../02-feature/export.md)，明确导出范围、导出字段和文件下载方式。
